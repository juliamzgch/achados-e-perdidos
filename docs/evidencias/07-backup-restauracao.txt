Legenda: backup atualizado do volume fotos (inclui o PNG de 1,4 MB) e restauração íntegra em volume novo, validada por SHA-256.

Comandos para reproduzir o backup e a restauração sem sobrescrever o volume ativo.
Execute na raiz do projeto; confira os nomes dos volumes com `docker volume ls`.
Esta reprodução cria `/tmp/fotos-backup-reproducao.tar.gz` e um volume
temporário chamado `fotos_restauradas`. Antes de executar, confirme que esse
volume e o arquivo temporário não existem ou substitua os nomes por nomes
livres. A sequência não remove o volume restaurado automaticamente. Ela não
foi executada para gerar as saídas históricas mostradas abaixo.

```sh
docker run --rm \
  -v achados-perdidos_fotos:/data:ro \
  -v /tmp:/backup \
  alpine:3.21 \
  tar -czf /backup/fotos-backup-reproducao.tar.gz -C /data .

docker volume create fotos_restauradas
APP_UID="$(docker compose exec -T web id -u app)"
APP_GID="$(docker compose exec -T web id -g app)"
docker run --rm \
  -e APP_UID="$APP_UID" -e APP_GID="$APP_GID" \
  -v fotos_restauradas:/data \
  -v /tmp:/backup:ro \
  alpine:3.21 \
  sh -c 'tar -xzf /backup/fotos-backup-reproducao.tar.gz -C /data && chown -R "$APP_UID:$APP_GID" /data'

docker run --rm -v achados-perdidos_fotos:/data:ro alpine:3.21 \
  sh -c 'cd /data && sha256sum * | sort'
docker run --rm -v fotos_restauradas:/data:ro alpine:3.21 \
  sh -c 'cd /data && sha256sum * | sort'
rm /tmp/fotos-backup-reproducao.tar.gz
```

Depois de verificar os hashes, remova `fotos_restauradas` somente se foi o
volume temporário criado por você para essa reprodução.
